# Contributing to Kubereum

Thanks for your interest. This file covers the basics of working with our open source repositories.

## Reporting issues

- Search existing issues first to avoid duplicates
- Use the issue templates where they exist
- Include version numbers, steps to reproduce, and expected vs actual behaviour
- For security issues, do not file a public issue. Email security@kubereum.com instead. See [SECURITY.md](SECURITY.md) for the full process

## Suggesting changes

- Open an issue first for anything larger than a typo or small bug fix
- Wait for a maintainer to confirm the direction before opening a pull request
- Small fixes can go straight to a pull request

## Pull requests

- Fork the repository, create a branch from `main`
- Keep changes focused. One logical change per pull request
- Write a clear title and description. Reference any related issues
- Add or update tests where appropriate
- Run the existing test suite before pushing
- Sign your commits if the repository requires it

We review pull requests in order. Expect a first response within five working days. Larger changes may take longer.

## Code style

Each repository has its own conventions. Look at recent files in the area you are touching, or check the repository README for specifics.

## Licensing

By contributing, you agree that your contributions will be released under the same license as the repository you are contributing to.

## Questions

For everything else, write to opensource@kubereum.com.
